# 05 数据工程与偏差防线

## 数据分层

1. Raw：原始响应或文件，只追加，不原地修改；记录来源、获取时间、校验值。
2. Clean：类型、时区、交易日历、重复和异常处理确定化。
3. Point-in-time：按“当时可见”还原历史，保存修订与公告时间。
4. Features：由配置和代码生成，禁止手工改表。
5. Results：保存输入版本、代码版本、参数和运行日志。

## 七类致命偏差

- 前视偏差：用到未来价格或未来才发布的数据。
- 幸存者偏差：今天仍上市的资产倒推历史，遗漏退市失败者。
- 选择偏差：看过结果后选择资产、时期或指标。
- 数据窥探：反复调参直到测试集最好。
- 修订偏差：使用后来修订的宏观/财务数据。
- 标签泄漏：预处理、缺失填充或特征直接包含目标期信息。
- 执行偏差：假设在不可成交的价位或容量上成交。

## 数据质量检查

- 主键唯一；日期单调；资产-日期重复为零。
- OHLC 逻辑：`low <= open/close <= high`；价格和成交量非负。
- 缺失按原因分类：未上市、停牌、节假日、数据故障不能统一填充。
- 极端收益回看公司行动和原始记录，不能仅 winsorize 掉。
- 随机抽取资产与日期，和第二来源/原始页面核对。
- 每次更新比较行数、日期范围、空值率、分布和断点。

## 时间对齐测试

用一张只有 5 行的手工表证明：第 t 日收盘后计算的信号，最早在 t+1 可成交价格执行；持仓收益从实际成交之后计算。测试应在错误使用同日收益时失败。

## 许可与合规

公开可访问不等于可批量抓取或商用。记录数据许可、速率限制、归属要求和再分发限制；涉及真实交易时再核对当地监管、券商协议和税务要求。
