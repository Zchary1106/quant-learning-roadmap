# 09 交易执行与实盘工程

## 研究系统与交易系统分离

研究系统允许探索，交易系统必须确定、可审计、可恢复。生产输入只接受版本化策略和配置；Notebook 不直接连真实下单接口。

## 事件驱动骨架

`MarketData → Strategy → Portfolio/Risk → OrderManager → BrokerAdapter → Fill → Accounting`

每类事件带唯一 ID、事件时间、接收时间和来源。状态变化写审计日志；系统重启后能从快照和事件重放恢复。

## 订单状态机

典型状态：Created → Submitted → Acknowledged → PartiallyFilled → Filled/Cancelled/Rejected。必须处理乱序、重复回报、部分成交、撤单与成交交叉。幂等键防止网络重试生成重复订单。

## 模拟交易分层

1. 历史回放：验证逻辑与性能；
2. Paper broker：验证实时数据、时钟、订单生命周期；
3. Shadow mode：生成但不发送订单，和人工/旧系统对比；
4. 极小资金：验证真实费用与异常处理；
5. 逐步扩容：容量和风险指标持续达标才增加。

每一层有进入与退出标准。Paper 成功不证明真实成交质量。

## 监控

监控数据新鲜度、时钟偏移、策略心跳、目标/实际持仓、未决订单、拒单率、成交滑点、PnL、风险限额、磁盘与网络。告警要有负责人、严重度、处置手册和演练记录。

## 安全边界

API 密钥最小权限，研究与交易账户隔离；提款权限关闭；下单端有资产白名单、单笔/日累计/仓位硬限制和 kill switch。日志隐藏密钥与个人信息，依赖与镜像固定版本。
